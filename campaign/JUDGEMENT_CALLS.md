# SynTrustBench v0.4 implementation judgement calls

The explicit request to retain the reference component's statistics governs that component. The working specification governs the full scientific campaign; the engineering prompt governs execution and evidence handling. No expected control verdict is forced.

## Data, roles and comparisons

1. **Frozen splits take priority.** Their hashes are verified, and their patient-audit sidecar is required. Missing patient provenance yields declared unavailability rather than resplitting anonymous data. Raw encounter-flow details absent from a frozen export are not reconstructed.
2. **Raw cohort preparation reuses the previous notebook's rule:** minimum numeric encounter ID per patient, stable sorting, `<30` target, no diagnosis regrouping or external imputation, `?`/empty as missing while literal `None` remains a category. Duplicate encounter IDs or unknown outcome labels raise errors.
3. **Split seed interpretation.** The first 80/20 split uses 49173. The development 50/50 split uses a semantic SHA-256 seed derived from `(49173, "half")`. Exact old memberships are guaranteed only by loading the frozen splits; the old notebook used a different JSON seed serialization.
4. **C→R/P assignment.** One stratified 50/50 split is used with a semantic role seed. A possible extra row is omitted to keep R/P equal. Floor T is a stratified n=|R| subsample of full T. The floor is deliberately a subset of T, while T/R/P/E are pairwise patient-disjoint.
5. **Training and comparison sizes.** Generators fit on full T and produce |T| rows. Candidates are subsampled without replacement to |R| with a recorded semantic seed. The same candidate is used for the official and v0.4 profiles and for all judges.
6. **Official-profile comparator.** Official v0.3 receives the same size-matched floor T and candidate used by reference Utility, plus E. Its estimator code and thresholds are untouched. These are new official-v0.3 evaluations under the v0.4 role design, not byte-for-byte reproductions of prior full-T campaign results. The official privacy member set is consequently the floor subset; v0.4 Privacy uses full generator-training T, as required. Both row counts are reported.
7. **Patient identity versus identical analytic rows.** The separate audit establishes patient disjointness. v0.4 Privacy permits distinct patients with identical analytic rows so the E-in-T coincidence rate can be nonzero. It reuses frozen coercion and target mapping but does not run v0.3's analytic-overlap rejection for this test. The original ReferenceContext and official evaluator retain their stricter validation; a collision rejected there is surfaced, not silently removed.
8. **Null size design.** Each repetition repartitions T∪C into 40% pseudo-T, 40% pseudo-C, 20% pseudo-E, then splits pseudo-C into R/P. Floor and candidate are matched within repetition. Thus null reference/candidate sizes are about 20% of development, smaller than the main reference. Main E is never used. Repetitions reuse development patients; this is not patient-independent replication across runs.
9. **Positive/control replication.** Three control repetitions use seeds 17/29/43. Positive replicates are seeded subsamples/orderings of the fixed P pool. Since P is approximately the comparator size, their patient sets are nearly identical; they are not three independent real samples. Copy replicates sample full T; negative controls independently permute columns of the matched floor, retaining exact empirical marginals.

## Reference evaluators and evidence policy

10. **Reference calculations are preserved.** `reference.py` and `results.py` are the prior delivered component. Models, encoders, pooling, thresholds, chance correction, bootstrap formulas and fixed 95% intervals are unchanged. Raw outputs remain under `raw_reference`.
11. **Parallel/resume RNG boundary.** The real-only context is built once per main/null role set and saved. Each table loads a private copy of its post-construction RNG state, then calls Fidelity before Utility. This preserves each call's implementation and permits deterministic independent jobs; it deliberately does not replay the previous validation script's cross-table RNG advancement. Stressor Utility comparisons replay the same pre-Utility bootstrap state. The policy is frozen and recorded.
12. **Missing evidence wrapper.** Original nonfinite filtering and missing-value behavior are not rewritten. The wrapper blocks Pass for missing required calibration signals or entirely missing continuous columns in candidate/reference/floor. Undefined reported metrics receive explicit `NotEvaluated` metadata. Descriptive metrics are not automatically made decision-driving. Fail still precedes missing evidence.
13. **Calibration references and warnings.** O/E and slope remain relative to the real-training logistic model, not the model trained on R. Rare categorical levels beyond 250 are pooled. Detection intervals omit classifier-refit variance. These inherited limitations are recorded rather than statistically “fixed.”
14. **Reference seed exceptions.** The explicitly specified generator seeds, split seed and null-assignment seed remain fixed. New job/sampling/injection seeds use semantic JSON keys. ReferenceContext uses its configured seed; real-only caches and per-job independent evaluators use separate declared seeds, without a global counter.

## Privacy, Equity and Robustness

15. **Exact-copy test.** A one-sided binomial test uses the empirical fraction of E rows whose full canonical row appears in full T as its plug-in null probability. Significance is 0.05. No smoothing or uncertainty integration for that estimated null probability is added; in particular a zero observed coincidence rate remains zero. Exact comparison retains v0.3's canonicalization.
16. **Privacy estimators and caching.** The frozen distance/attack code is adapted into a separate additive module. Real-only encoding, sampled member reference, neighbor fit and real–real floor are cached once per role set with a recorded seed. Candidate sampling/bootstrap and released-table attacks remain per profile. The installed official helper is not patched.
17. **Low-FPR support.** TPR at 0.1% requires at least 1,000 sampled nonmembers; TPR at 1% requires at least 100. Below that resolution the metric is explicitly `NotEvaluated`. These exploratory TPRs do not drive the gate because reliable low-FPR uncertainty was not specified. Attack AUC remains decision-driving; the attack is labeled a weak lower bound.
18. **Subgroup eligibility.** Eligibility is defined using the held-out subgroup sample/class counts (defaults 30 and 10 per class). Below-support groups are retained as explicit unavailable rows, outside the eligible decision set. Any eligible group with a weak TRTR baseline blocks a fully evaluable aggregate; no eligible groups means Equity `NotEvaluated`.
19. **Equity rules.** Eligible-group retention uses the same 0.80/0.90 CI decision rule as primary Utility, with paired E-row bootstrap versus subgroup TRTR. Representation gap is measured against R; its provisional Conditional threshold is 0.10. The absolute worst-group AUROC rule is removed. Worst retention is reported only when all eligible groups are evaluable.
20. **Meaning of robustness flip.** Any transition among `Pass`, `Conditional`, and `Fail` counts as a flip, in either direction, for any configured model-seed, missingness or training-size stressor. Transitions involving `NotEvaluated` indicate missing evidence, not a scientific reversal. Constant primary TSTR predictions or unevaluable Utility yield Robustness `NotEvaluated`.
21. **Robustness comparison protocol.** Stressors refit the full supplied Utility probe family; real-trained baselines remain fixed. The source notebook's model seeds, three missingness rates with three repetitions, and four training fractions are retained. Provisional variability thresholds are inherited from v0.3. Calibrated verdict flips are recomputed using the calibrated Utility rules. No unsupported temporal/site or generator-replicate stability claim is added.

## Calibration, judges and analysis

22. **Max-statistic procedure.** The old notebook's plug-in direction-aware empirical max statistic is reused: median harm center, sample standard deviation, scale floor 1e-8, maximum across eligible prespecified signals, and `quantile(method="higher")`; rejection uses strict exceedance. The 20 fit / 20 audit run IDs are assigned with seed 81631. This is not a finite-sample FWER guarantee, and target levels may share a cutoff.
23. **Signal menu.** Fidelity uses coverage deficit, AUC excess over its real floor, three low-order distance excesses, and constraint violation rate. Utility uses each probe's retention upper CI plus both directions of O/E and slope ratios. Privacy uses exact-match excess, closeness share and attack AUC. Equity uses representation gap and worst eligible-group retention. Robustness uses seed CV, bootstrap relative width, maximum-missingness AUROC drop and training-size spread. pMSE, worst-column distance and low-FPR TPR remain descriptive.
24. **Missing null metrics.** A signal unavailable in any fit repetition is explicitly listed, and its dimension cannot obtain a calibrated Pass. Other signals may still be calibrated, but the gate preserves the missing required evidence. If no signals are calibratable, calibration itself is unavailable and downstream scoring cannot proceed.
25. **Calibrated decisions.** Statistical provisional threshold flags are replaced by the frozen maxT wrapper; raw numbers and original descriptions are retained. Structural single-class outcome failure and the any-verdict-flip requirement remain. `calibrated_signals` carries effective raw thresholds/flags separately from original metric metadata. Empirical comparisons can therefore differ from provisional rules, including the clinical-constraint cutoff.
26. **Score normalization not specified by the source.** Each dimension's score is `exp(-max(0, maximum directional z)/3)` relative to the fitted real–real center and scale. The mapping and temperature are frozen in configuration before scoring; scale/location use fit-null runs only. Every required signal must be available. Scores are not clipped to arbitrary pass/fail labels or weighted by observed outcomes. A complete scientific utility interpretation of this normalization is not claimed.
27. **Compensatory judges.** Mean, geometric, harmonic and weighted means require all five dimension scores. Zero is treated mathematically (geometric/harmonic become zero); missing is never converted to zero or omitted. Weighted means use 0.25/0.25/0.25/0.15/0.10. “Geometric” is not attributed to Belgodere because that attribution is marked unverified in the spec.
28. **SDMetrics comparison boundary.** The native Quality Report overall score versus R is retained as the required external fidelity-only headline, rather than replaced with the five-dimensional normalization. Its unavailable properties are explicitly recorded, including native omission behavior. Acceptance by this external comparator is reported as its policy, not as a SynTrustBench Pass or a five-dimensional safety assessment.
29. **Positive-control τ*.** Each scalar judge uses the lowest score across all three planned positive replicates. Any missing positive score makes its threshold unavailable. Offsets are exactly 0, −0.05 and −0.10, without clipping. These comparator thresholds are derived after scoring positive controls (including Utility on E), as required by the spec; they are distinct from development-only empirical-null calibration and are not independently validated acceptance thresholds.
30. **Ranking inversions.** Pairs are known-bad nonzero injected tables/copy/negative controls versus clean generated tables. A strict `bad_score > generator_score` is an inversion; ties are not. Every planned pair must be evaluable for an overall fraction. Gate has no arbitrary scalar ranking and is explicitly unavailable for this analysis.
31. **Known-bad labels.** Nonzero injections with no actual changed cells are not labeled known-bad. Requested and realized doses are reported. Dose-zero is always the baseline, never a known-bad injection. Copy controls are bad for the overall gate because of privacy, while their fidelity/utility expectations remain acceptable.
32. **Minimum detected dose.** Detection means `Fail`; `Conditional` is not silently upgraded to failure. If the baseline already fails, incident failure is not identifiable. Missing doses make the overall minimum unavailable; an observed absolute minimum is separately labeled. No failure in a completely evaluated dose grid is distinguished from missing evidence.
33. **Selectivity.** Response is the baseline dimension score minus the injected score. Per-table selectivity is the maximum intended response minus the maximum off-target response. Figure cells average only complete expected replicate sets, separately for positive and GC baselines; any missing member yields NA rather than a partial mean. Intended dimensions are outlined.
34. **Audit denominators.** Strict Fail rates and non-Pass rates are reported separately. Wilson intervals and a clearly labeled subset rate use only evaluable runs, with missing/expected counts. The full audit false-alarm rate is unavailable if any planned audit run is unevaluable. `NotEvaluated` is never a non-detection.
35. **Threshold sensitivity.** For each table/dimension, the reported fraction is the share of target rates whose verdict differs from the primary 0.05 verdict; any missing verdict makes that comparison unavailable. Comparator τ-offset sensitivity is separately captured in the judge acceptance table.

36. **Smoke scope.** Small mode keeps the same code paths but uses capped rows, one epoch and seed per generator, one control replicate, four null runs split 2/2, and the largest specified nonzero dose per family plus zero. Nestedness is separately tested at every full-grid dose. These results are labeled smoke only. Full-mode preflight constructs a separate frozen small cohort from development patients, never main E.
37. **Resumption and concurrency.** Advisory per-job locks prevent duplicate writers; attempt directories are unique. Inputs and artifacts are SHA-256 checked before reuse. Only independent profile jobs use the process pool. Cache objects are trusted local artifacts and are loaded only after ledger verification. Unexpected errors are logged and re-raised; declared unavailable analyses are recorded explicitly.
38. **Dependency choices.** The exact package pins are in `requirements.txt` and notebook setup; Python 3.12 was used for validation, and pins support Python 3.11+. CUDA local-version suffixes are recorded in the numerical lock. Setup verifies every installed frozen Python source against the checked-out commit and rejects modified tracked checkout files. Notebook-library hashes also prevent implementation drift on resume.
39. **Scope of source reuse.** Cohort rules, the transactional ledger design, development-only null construction, nested injection blocks and max-statistic approach are adapted from the supplied v0.3 notebook. The source's old pending-null switch, Colab-only paths, broader nearest-neighbor approximation experiment and old stage names are not carried over because the current spec resolves or excludes them.
40. **Delivery and validation.** The notebook remains unexecuted. Temporary copies and generated schema-compatible data validate engineering behavior; they do not establish the hypotheses or reproduce any preliminary UCI result in the attached specification. The completed-job audit is separate from metric availability and scientific acceptance.

## Generator-extension judgement calls

41. **Additive scope.** DPAIM is mandatory through `enabled_names`; the existing three-generator configuration is retained. DPMST and TabDDPM are independent default-off flags. Every enabled generator uses the existing seeds, training rows, matched comparison sample and clean-stage profile path. No new injection baselines or scientific evaluator rules are added.
42. **Versions and isolation.** SmartNoise Synth 1.0.8 and MBI 1.1.0 are pinned; JAX/JAXlib 0.6.2, Optax 0.2.5, Chex 0.1.90, OpenDP 0.14.2, SmartNoise SQL 1.0.10, NetworkX 3.4.2, disjoint-set 0.9.0 and cloudpickle 3.1.2 are additionally pinned. Every original explicitly pinned numerical package stays at its delivered version. TabDDPM uses a separate Python 3.10 environment with Synthcity 0.2.12 and a full transitive, platform-marked, hash-checked lock. Python 3.10 is supplied by the user/system; the notebook does not silently substitute another Python version.
43. **Public numeric domains.** Tuples are `(lower, cap, integer bin width, overflow upper)`: hospital stay `(1,14,1,14)`; labs `(0,200,10,1000)`; procedures `(0,20,1,100)`; medications `(0,100,5,500)`; outpatient/emergency/inpatient counts each `(0,50,5,250)`; diagnoses `(0,30,2,100)`. These are declared modeling bounds, not estimated distributional limits or asserted clinical maxima. They are frozen before reading private data. The final regular bin can be shorter than the others. Above-cap counts share a finite overflow interval; values beyond its upper bound still map to that interval. Hospital stays clamp to 1–14 with no extra overflow category.
44. **Integer reconstruction and missing values.** Counts round to the nearest integer before fixed-bin encoding; below-bound values clamp. Each numeric column has a dedicated missing/nonfinite bin. Its output is the public lower bound, so generated counts remain integers and satisfy the clinical constraints. Other bins decode uniformly over their inclusive integer interval using the sample seed. This is lossy, zero-budget preprocessing/postprocessing and is not applied to other generators or reference calculations.
45. **Public categorical schema.** Race, gender, age bands, lab/medication categories and the binary outcome use explicit configuration levels informed by the public UCI dictionary. Identifier categories use conservative fixed public supersets: admission type 1–9, discharge disposition 1–30 and admission source 1–26. Missing and unknown categories are represented by fixed reserved tokens, except the binary outcome, which must be observed 0/1. No `.unique()`, private category fit or observed-level discovery is used. The SmartNoise label transformers are pre-fitted only on every code in these public domains, including unobserved levels.
46. **Diagnosis granularity and leakage.** Diagnosis values are reduced to the prefix before the decimal point. Numeric prefixes normalize leading zeroes and use the public range 0–999; V00–V99 and E000–E999 are also declared independently of the data. These broad ICD-9 syntax supersets can generate unused codes and lose decimal specificity, affecting fidelity/utility honestly. Unknown strings map to the fixed OTHER bucket. There is no private level-set leakage in the supplied defaults. If an analyst replaces the schema with levels extracted from training data, that change leaks level-set information and invalidates the stated zero-budget preprocessing assumption. Public schema must be justified independently of the protected training population.
47. **Resolved delta and unit of protection.** Each fit receives ε from configuration (default 1) and δ from configuration or `1/(10*n_train)`. The exact n and δ are recorded. Row count/domain are treated as public; one prepared row corresponds to one patient. The record reports the upstream SmartNoise unit-row mechanism's nominal ε/δ accounting, not a newly proved patient-level guarantee for cohort construction, membership-dependent splits, or the complete campaign. Public sample size and the upstream adjacency/accountant assumptions require review before a real private deployment.
48. **Private fit noise versus reproducibility — user-confirmed.** Keep OpenDP's unseeded Gaussian noise. Also replace the publicly seeded NumPy state temporarily with fresh, unrecorded OS entropy while the upstream mechanism selects marginals, restoring the caller's state afterward. The library itself is not patched. Seeds 17/29/43 remain fit identifiers; seeded sample generation and integer decoding from a fixed fit are tested. Identical refits from public seeds are intentionally not promised. Completed artifacts provide deterministic resumption without recording or releasing private fit randomness. This is the interpretation explicitly accepted by the user.
49. **Budget composition and release boundary.** Per-fit accounting appears in a separate provenance object/table, never as an empirical privacy metric, score or gate override. Multiple AIM/MST fits, retries and any real-data smoke fits consume additional privacy budget if their releases are combined; an ε=1 per-fit setting does not make the multi-seed campaign ε=1. Basic composition sums ε and δ for released fits under the same applicable adjacency assumptions; no tighter composition claim is made. This notebook is a benchmark, not a DP release service: raw/frozen tables, exact diagnostics, dataset hashes, other generators and evaluator reports remain outside the guarantee.
50. **AIM compute.** Degree-two public workload, maximum marginal cells 10,000 and model-size setting 80 MiB follow the pinned API defaults and are recorded. Full mode uses upstream adaptive round selection; smoke requests 32 initial-budget rounds (at least enough for all 21 one-way marginals). This is a budget-allocation setting, not a promise of exactly 32 iterations or a hard peak-memory cap. MST uses its upstream mechanism unchanged. Full-data runtimes and resource use were not measured.
51. **Optional TabDDPM protocol.** Synthcity's `ddpm` plugin uses CPU, classification mode for the declared binary target, batch size at most 256, default 1,000 training epochs and diffusion timesteps, with one epoch and ten timesteps in smoke. Its private training copy imputes missing numeric predictors to 0 and categorical values to a reserved missing token; the latter is restored after generation. This fixed imputation belongs only to this non-DP optional adapter. Output columns and row counts are checked after CSV exchange. No claim that TabDDPM provides DP is made.
52. **Optional setup failures.** Python absence, build failure/timeout and failed plugin import probes are declared environment unavailability, with command logs and hashes. These jobs and downstream profiles remain visible as Unavailable; they do not abort main scoring or full-mode preflight. Successful environment construction does not excuse later scientific errors: unexpected fit/sample failures still propagate with tracebacks. The default setup timeout is two hours and can be configured.
53. **Optional environment provenance.** A content-addressed environment is shared across sequential generator fits, protected by a build lock. The complete resolved lock is installed with `--require-hashes --no-deps`, then `pip check` verifies closure; this avoids a hash-mode extras-resolution issue in the initial Python 3.10 installer. Runtime packages are fully pinned/hashed, while native build tools are platform prerequisites rather than a claim of bitwise-reproducible builds. Source hashes for Synthcity and package-version snapshots detect drift. The worker and lock hashes enter provenance, and the requirements text enters the main implementation lock. Synthcity never enters the SDV interpreter. The local build installed successfully but its plugin probe could not load XGBoost's OpenMP library (`libomp.dylib`), so no actual TabDDPM fit/sample is claimed as validated. No substitute model is silently used.
54. **Unavailable resumption.** Unavailable attempts now retain artifact hashes and elapsed time, and unchanged unavailable jobs reuse their existing state. Explicit retries permit downstream judges, analysis and report to create new attempts when dependency states change. Scientific input changes still require a new campaign; old attempts remain intact. This small ledger extension is needed so optional unavailability does not invalidate otherwise cached reports on every rerun.
55. **Validation scope.** The DP tests verify real adapter schema/row count, integer/nonnegative counts, stay bounds, resolved delta, public-domain invariance under changed private extremes and novel private categories, same-fit sampling determinism, and persistence. Optional environment failure is exercised explicitly. Artificial-data instrument tests and small generator fits do not validate real-UCI utility, a full-campaign privacy composition, formal implementation security, or full-data resource bounds. See VALIDATION.json for the actual final execution coverage and any optional-plugin gap.

Sources for the extension: [SmartNoise synthesizer API](https://docs.smartnoise.org/synth/synthesizers/index), [SmartNoise 1.0.8 package](https://pypi.org/project/smartnoise-synth/1.0.8/), [UCI dataset dictionary](https://archive.ics.uci.edu/dataset/296/diabetes+130-us+hospitals+for+years+1999-2008), and [Synthcity 0.2.12](https://pypi.org/project/synthcity/0.2.12/). Exact installed/wheel sources were inspected for the pinned adapters.

## Exact-row coincidences between patient-disjoint real roles (added 2026-11-05)

v0.3 `load_submission` stops when any held-out real row exactly matches a training row. Null repetition 07 hit this with one row shared by two different patients (patient hashes disjoint). `ReferenceContext` now validates each real table with the frozen v0.3 helpers (`_coerce_frame`, `_map_target`) and records `exact_row_coincidences` (floor vs reference, floor vs test) in `reference_context_summary.json` instead of stopping. Reason: every role is asserted patient-disjoint by hashed ID upstream, so such rows are real-real coincidences, the quantity the v0.4 privacy null already models; rejecting or re-drawing those runs would select the null sample. With no coincidences, outputs are identical to the supplied reference (checked: floor, baselines, RNG state, fidelity, utility at 1e-12). The campaign restarted under `runs/main_v2`; `runs/main` is kept as the record of the stop.

## v0.4.1 amendment: gate-focused protocol (added 2026-11-06, before any v0.4.1 scoring)

The claim was locked first: averaging lets one serious failure hide behind good scores; a gate that requires every dimension to pass catches it, but only once each dimension is calibrated against real-vs-real comparisons. Every change below serves that test and was fixed before any v0.4.1 job ran. The v0.4 run (`runs/main_v3`) is kept unchanged as the evidence that motivated the amendment.

1. **Gate over fidelity, utility and privacy only.** In the v0.4 audit, the robustness rule ("any utility verdict flip fails") rejected 15 of 20 honest audit runs. Equity was NotEvaluated on most honest runs, because one weak real subgroup removed the whole dimension. A non-compensatory gate inherits its least specific dimension's false alarms, so admitting either would make the gate reject real data. No published benchmark gives a validated decision rule for these two (Synthcity, SynthEval and Yan et al. 2022 omit them; Vallevik et al. 2024 list fairness metrics without thresholds). They are still computed with their v0.4 rules and their own calibration family, reported in every table and figure as diagnostics, and never change the verdict.
2. **Admission rule (prespecified).** A dimension may gate only if, on every held-out audit run, it is evaluable and an exact one-sided binomial test finds no excess non-acceptance over the 5% target (p ≥ 0.05; at most 5 of 50). It applies identically to all five dimensions and to the gate. The rule tests "no evidence of excess" because 50 runs cannot demonstrate an upper bound below 5% (0 of 50 gives a Wilson upper limit of 7.1%). If a declared gating dimension fails the rule, the report says so, and thresholds are not re-tuned.
3. **Full-conformal calibration.** In v0.4, Fidelity was rejected on 4 of 20 audit runs, all through one spiky coverage-deficit signal. The four largest of the 40 values all fell in the audit half (probability about 5% by chance), and the old rule standardized fit runs with statistics that included themselves. v0.4.1 pools each new table with the fit runs, standardizes, and rejects if its maximum exceeds the floor(α(n+1))-th largest fit-run maximum. That has exact marginal level floor(α(n+1))/(n+1) if honest tables are exchangeable with the fit runs, whatever the signal's shape (Vovk et al. 2005; Lei et al. 2018). The gate family and the diagnostic family are calibrated separately, so diagnostics cannot loosen or tighten the gate. A fixed fit-run median and SD are kept only for the frozen compensatory score mapping and for descriptive per-signal thresholds.
4. **100 fresh null runs (50 fit / 50 audit).** New seeds (salt `v0.4.1`), so none of the v0.4 runs that motivated the change are reused in the confirmatory audit. Smoke mode uses 5 runs (3 fit), which cannot reject at these α levels; that is recorded as `finite_sample_valid: false`, not hidden.
5. **Judges.** The weighted judge is removed. With the equal default weights used in published practice it equals the mean, and any unequal weights would be an unprespecified choice. The remaining judges are gate, mean, geometric, harmonic and native SDMetrics; the `judge_provenance` table maps each to published practice. Compensatory judges average the same three gating dimension scores. Every judge is now also scored on the 50 held-out honest audit runs, so both errors are measured: known-bad acceptance and honest-data rejection.
6. **Headline known-bad set.** Real data with exactly one serious flaw: injections on the positive controls, plus the copy control. Negative controls and injections on generator tables are reported separately, because those baselines already fail.
7. **Injection intended dimensions** now name gating dimensions only. Subgroup suppression maps to fidelity, its only route through the gate; this documents what the narrower gate can and cannot see.
8. **Matched-rate judge comparison (primary).** Under the v0.4 rule τ* (lowest score among 3 positive controls), each judge ends up at a different honest-data rejection rate, so known-bad acceptance is not compared at equal cost. In v0.4.1, every compensatory judge is calibrated on the same 50 fit runs with the same full-conformal pooling as the gate: each run's three dimension scores and combined score are computed with the candidate pooled in, and the table is rejected below the floor(α(n+1))-th lowest fit-run score. SDMetrics, whose score does not depend on the fit runs, uses the same order statistic of the fit runs' native scores. All judges therefore share nominal honest-data rejection floor(α(n+1))/(n+1). τ* is kept as a secondary analysis. Prespecified expectation, from max-type versus sum-type tests: at matched cost the gate accepts fewer single-flaw tables than the arithmetic mean and SDMetrics, while the harmonic mean, which is dominated by its lowest score, may come close to the gate. A dry run of the new analysis code on the v0.4 profiles (old split, non-confirmatory) showed this pattern; that run tested the code only and is not evidence.
9. **Unchanged:** frozen v0.3 (reported as the uncalibrated five-dimension baseline), all reference statistics (regression fixture), generators, doses, splits, privacy, equity and robustness metric code, and the exact-row coincidence policies above.

## v0.4.2 follow-up amendment (7 November 2026, before any follow-up table was scored)

The full design and analysis plan are in `PREREGISTRATION_v0.4.2.md`. The judgement calls:

1. **Audit null runs become the bases.** Review showed that the main_v5 known-bad set is one base
   table with three injection seeds, and that main-experiment tables are larger than the null runs
   the calibration was fitted on. Injecting the same flaws into the 50 held-out audit candidates
   fixes both: 50 independently split bases, each at the fit runs' role sizes. The bases are processed
   in the frozen audit order, so a partial run is a random subset.
2. **Nothing frozen changes.** The follow-up uses the exact library that produced main_v5 (checked
   against `implementation_hashes.json`), the frozen calibration model (checked by SHA-256), the saved
   reference context of each audit run, and the campaign's own judges. No model is refit.
3. **The frozen v0.3 profiler is not run.** It is not part of any follow-up comparison and would
   triple the cost per table.
4. **Dense flaws use three mild components fixed in advance**, one per gating dimension: F
   (`number_inpatient` rotated in 50% of rows), U (outcome rotated in 10% of rows) and P (one training
   row copied in). Doses were chosen from main_v5 evidence and the code, not from follow-up results.
   Outcome rotation reuses the campaign's `feature_shuffle` perturbation with the outcome as the
   column, so prevalence is unchanged.
5. **Seed streams are per base and per flaw family**, so doses of one family are nested and every
   dense combination contains exactly the changes of its parts. F alone is the single-flaw cell
   `feature_shuffle@0.5` and is not rerun.
6. **Supplementary audit runs use repeat ids 100 to 249** with the v0.4.1 seed salt, so they are fresh
   draws by the same procedure, and are scored only with the frozen model. Their roles and contexts
   are deleted after scoring to save disk space; their profiles are kept.
7. **Calibration is also validated by reshuffled splits** of the 100 main_v5 null runs (1,000 random
   50/50 splits, refit with the campaign's `NullCalibrator`), computed from saved evidence. The frozen
   model remains the one used for every decision.
8. **A table a rule cannot score counts as not accepted** by that rule, and such cases are reported.
